# Макет: живой файл Figma

Размеры, цвета, тексты и ассеты берутся из файла Figma с открытым dev-режимом, и
больше нигде. Скриншотов макета в репозитории нет: обзор целого отдаёт
`get_screenshot` по узлу фрейма, любым размером и всегда свежий, а лежащая в
`docs/` картинка молча устаревала бы, выглядя при этом источником истины.

Копий значений здесь тоже нет. Цвета, радиусы и тени живут в
`src/styles/variables.css`, остальные числа — в стилях секции рядом с вёрсткой.
Таблица «токен — значение» в документе означала бы одно число в двух местах, и на
прошлом проекте они уже расходились. Записан только адрес — где смотреть, если
понадобится сверить.

Числа, стоящие внутри разбора в `docs/adr/`, под запрет не попадают: это замер, на
котором держится вывод, а не справочник, к которому пойдут за актуальным значением.

## Адрес

Заводится проектом в первой же задаче по вёрстке и живёт здесь:

- файл — `<fileKey>`
- страница — `<nodeId страницы>`

Ниже адреса проект держит карту узлов по секциям: имя компонента, что внутри и
номера узлов обеих раскладок. Пустой таблицы в шаблоне нет намеренно — пустая графа
читается как долг, и её пойдут заполнять, чтобы не осталось пусто.

Инструменты — Figma MCP. `fileKey` и `nodeId` передаются двумя отдельными
параметрами, поэтому ссылка на макет не нужна: из неё те же два значения пришлось
бы извлекать вручную. Дефис в номере узла — та же запись, что двоеточие:
`node-id=1-556` из ссылки и `1:556` из таблицы ниже — один узел.

| Что нужно                          | Чем берётся          |
| ---------------------------------- | -------------------- |
| состав узла, его стили и размеры   | `get_design_context` |
| список вложенных узлов с номерами  | `get_metadata`       |
| картинка узла для контроля глазами | `get_screenshot`     |
| SVG иконок и исходные заливки узла | `download_assets`    |

## Текст читается из `get_metadata`, а не из полного ответа

Figma называет текстовый слой его содержимым, и `get_metadata` отдаёт имена. То
есть тексты всей секции приезжают одним дешёвым вызовом, тогда как
`get_design_context` по тому же узлу тянет за собой всё дерево иллюстрации — доходило
до двадцати шести ассетов ради трёх абзацев.

Порядок такой: `get_metadata` по секции даёт тексты и номера узлов, после чего
`get_design_context` спрашивается **по самому текстовому блоку** — кегли, вес,
цвет и высота строки нужны только с него.

**Имя слоя при этом не всегда текст.** Слой, переименованный из компонента, несёт
имя компонента, а не содержимое: «Button name» вместо «Скачать презентацию». Имя,
похожее на служебное, обязано быть перепроверено полным ответом.

**Ответ по узлу как корню не отдаёт его собственную заливку.** Спросили полосу — в
ответе битмап, а плашка под ним приходит пустым `div`. Заливка читается из ответа по
родителю либо из экспорта — см. ниже.

## Заливка сложной фигуры лежит в экспорте, а не в стилях

Тёмные полосы с вырезом под логотип или кнопку рисуются в макете
`boolean-operation`. Инструмент отдаёт такую фигуру картинкой, а не стилями, поэтому
цвет, радиус и обводка снимаются с самого файла: `download_assets` (или URL ассета из
`get_design_context`) → SVG → `fill`.

**Экспорт узла показывает и то, чего в композите нет.** Скрытый нулевой
прозрачностью прямоугольник приезжает в экспорте живым: метаданные такой слой от
видимого не отличают, `hidden` у него не стоит, а корневой ответ по нему собственных
стилей не отдаёт вовсе. Так однажды чуть не уехал чёрный фон полосы вместо настоящего
тёмно-серого. Проверка одна: `get_screenshot` по узлу на обеих раскладках — цвет
снимается с композита, а не с экспорта отдельного слоя.

**Заливка бывает на фрейме, а не в дочерней плашке.** Если дочерний узел с фоном в
файле скрыт, в метаданных видимого фона нет вовсе — он приходит только экспортом
фрейма. То же с заливкой самой страницы: корневой ответ её не показывает, а в SVG
рамка рисует себя `<rect fill="…">`.

## Иконка выгружается вместе с предковым холстом

`download_assets` по узлу иконки отдаёт её вместе с холстом предка: в файле
оказываются `<rect fill="#1E1E1E">` во весь кадр и путь на минусовых координатах
(`M-1918 -10652 …`).

Чистится это руками: из экспорта берётся поддерево нужной группы, вокруг него
пишется `<svg>` с `viewBox` по размеру узла. Проверка — список заливок в файле: у
чистого знака остаются только его собственные, `#1E1E1E` холста в нём нет.

Мелкие иконки дешевле брать по URL из ответа `get_design_context`: там каждый слой
уже отдельным файлом и без холста.

**Инлайновый `style` в экспорте перебивает каскад.** На корне `<svg>` приезжает
`style="display: block"`, и правило `display: none` его уже не гасит. Ловушка ждёт
любую иконку, которую что-то переключает; иконке, которую ничто не переключает, он
не мешает.

**Выгруженный SVG — не всегда то, что уедет в сборку.** Форму файла стоит проверить
глазами, а не принять на веру.

## Полпикселя в одном узле ряда — подгонка макета, а не число

Кегль читается с узла, но ряд однотипных узлов читается целиком: если у одного из
трёх соседей значение отличается на доли пикселя, это след подгонки текстового блока
под ширину, а не решение о типографике. Перенеси её — и в одном ряду окажется два
кегля, которых глазом не отличить.

Правило узкое: оно про ряд одинаковых по роли узлов. Разошлись роли — переносятся оба
числа.

## Ручной перенос строки внутри слова — не текст

«видеомони-торинга» в узком фрейме — подгонка под ширину, а не часть копирайта.
Такой дефис в разметку не переносится: на любой другой ширине он окажется посреди
строки.

## Гарнитуры: свои одна-две, остальные фолбэки

Open Sans 400/600/700 лежит в шаблоне локально и подключается через `astro:assets`.
Вторая гарнитура заводится, только если она есть в макете, — и тем же способом.

`Roboto`, `Segoe UI`, `Manrope`, `Mulish` в ответах инструмента — фолбэки макета: они
стоят на узлах, где рядом объявлен свой шрифт, и переносить их не нужно.
