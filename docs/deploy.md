# Выкладка на хостинг

Лендинг статический: одна страница, никакого рантайма. Ни Node на сервере, ни
переменных окружения, ни сборки на хосте не нужно — нужен только веб-сервер,
раздающий файлы.

## Перед первой выкладкой

**Форма заявки никуда не отправляет данные.** `send()` в
`src/scripts/request-form.ts` пишет их в консоль браузера: валидация, маска и
подтверждение работают, посетитель видит «спасибо», а заявка теряется. Пока
эндпоинт не подключён, боевая выкладка собирает заявки в никуда. Точка врезки
запроса одна — эта функция.

**Домен вписан в сборку константой** (`site` в `astro.config.mjs`), и от него
считаются `canonical`, Open Graph и карта сайта. Второе место — `Sitemap:` в
`public/robots.txt`. Сменить домен правкой на сервере нельзя, только пересборкой; в
шаблоне там стоит заглушка `https://example.invalid`.

## Сборка

Зависимости ставятся **только Yarn**. `npm install` при наличии `yarn.lock`
перепишет его под себя и сломает установку у коллег на других платформах — почему
именно, разобрано в `CLAUDE.md`.

```
yarn install --frozen-lockfile
yarn build          # astro check && astro build
```

На выходе — папка `dist`. Source maps не генерируются. Заливается **содержимое**
`dist`, а не сама папка: корень сайта — `dist/index.html`.

## Сжатие

Самое дорогое, если о нём забыть: у лендинга почти вся страница — инлайновые SVG,
и `index.html` легко весит под двести килобайт сырым при сорока под gzip.

Сжимать: `.html`, `.css`, `.js`, `.svg`, `.xml`, `.txt`.

Не сжимать: `.webp`, `.avif`, `.png`, `.woff2` — они уже сжаты, повторный проход
только тратит процессор.

## Заголовки кэша

Всё в `/_astro/` названо по хешу содержимого, включая шрифты, — эти файлы можно
кэшировать вечно. `index.html`
кэшировать нельзя: иначе вернувшийся посетитель не увидит новую вёрстку.

| Что                             | `Cache-Control`                       |
| ------------------------------- | ------------------------------------- |
| `/_astro/*`                     | `public, max-age=31536000, immutable` |
| `/` и `/index.html`             | `no-cache`                            |
| `/og-image.png`, `/favicon.svg` | `public, max-age=3600`                |
| `/robots.txt`, `/sitemap*.xml`  | `public, max-age=3600`                |

`og-image.png` стоит отдельного внимания: имя у него без хеша, а мессенджеры
держат превью в своём кэше долго. После замены картинки её придётся протолкнуть
через отладчики WhatsApp и Telegram вручную.

## MIME-типы

Astro раскладывает картинки в `.avif` и `.webp`. Старые сборки nginx про avif не
знают и отдают `application/octet-stream`. Проверить, что в `mime.types` есть:

`image/avif`, `image/webp`, `font/woff2`, `image/svg+xml`, `application/xml`.

Если включён `X-Content-Type-Options: nosniff`, это становится критичным: с ним
неверный тип у модульного `.js` даёт белую страницу вместо сайта.

## Домен и протокол

`canonical`, `og:url` и `sitemap-0.xml` содержат абсолютный адрес из `site`. Нужны
постоянные редиректы на этот вид:

- `http://` → `https://`
- `www.<домен>` → `<домен>`

Без них поисковик получит дубли страницы, а превью в мессенджерах будут вести на
неканоничный адрес.

## SPA-фолбэк не включать

Страница одна, и настроить «любой путь → `index.html`» соблазнительно. Делать
этого не надо: такой фолбэк отдаёт 200 на любой мусорный URL, и в индекс лезут
дубли. Несуществующий путь должен отвечать 404.

```nginx
root /var/www/<проект>/dist;
index index.html;

location / {
    try_files $uri $uri/ =404;
}

location /_astro/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
}

location = /index.html {
    add_header Cache-Control "no-cache";
}
```

## Порядок выкладки

Сначала `_astro` и остальная статика, затем `index.html` — тогда не возникнет
окна, в котором свежий HTML просит ещё не залитые чанки.

Старую папку `_astro` в тот же момент не стирать: у посетителя с открытой
вкладкой догрузка чанков должна пережить деплой. Достаточно удалить её со
следующим релизом.

## Проверка после заливки

```
curl -I https://<домен>/                 # 200, text/html, no-cache
curl -I https://<домен>/robots.txt       # 200
curl -I https://<домен>/sitemap-index.xml
curl -I https://<домен>/og-image.png     # 200, image/png
curl -I https://<домен>/_astro/<любой>.avif  # image/avif, immutable
curl -I http://<домен>/                  # 301
curl -I https://www.<домен>/             # 301
curl -I https://<домен>/нет-такой-страницы  # 404, не 200
```

Дальше — то, что делается один раз после первой выкладки:

- подтвердить сайт в Google Search Console и Яндекс.Вебмастере, указать регион;
- прогнать Lighthouse отдельно на 390 и 1440: цифры, снятые на localhost без TLS,
  боевыми не считаются;
- проверить превью ссылки в отладчиках WhatsApp и Telegram.
